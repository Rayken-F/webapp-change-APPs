# OQC RC V0.1.6 — 未建IQC鋼瓶 CTN 收錄

## 作業定位與界線

庫存掃描主要蒐集裝框出貨的單支鋼瓶 CTN；IQC 的 RT／鋼瓶狀態是唯讀附加資料。這次新增的是 RC 功能，不是正式上線核准。只新增 FAST RC 目錄腳本、調整該頁載入與版本；不修改正式 DS 工作台、IQC、Grinding、ERP、Timestamp 或後端。

## 新增行為

- 正常 IQC 查詢回應具有完整 IQC 集合欄位，且為當次 CTN 精確查詢，找不到單支鋼瓶時，允許收錄該 CTN。
- 項目保存 iqcLookupStatus=NOT_FOUND、iqcCheckedAt，RT／鋼瓶狀態／IQC 日期留空，不使用 0 或 UNKNOWN 冒充料號。
- 資料列不顯示 RT 或鋼瓶狀態；原 OQC 待檢位置改成紅色「未建IQC」，保留掃描時間。已建 IQC 的兩行顯示及 RT 轉換顯示不變。
- 未建 IQC 項目集中在獨立「未建IQC」開放批次，不從當前 RT 批次借用 RT。重用既有該類 OPEN 批次；正常 OQC-YYYYMMDD-01…99 編號不變。
- 可分次加入、計數、左滑作廢／原有復原流程、完成本機掃描批次；保留事件。未建 IQC 群組本版不提供手動 RT 更改，以維持 RT／狀態留空。
- 重複 CTN 在 IndexedDB 交易內檢查；未建IQC項目、批次、事件、目前批次選取在同一交易提交後才更新畫面。
- 逾時、斷網、登入失效、不完整或不相符回應不等於未建 IQC；不會以 NOT_FOUND 假入帳。此版遇到這些錯誤仍提示未加入並要求恢復連線重掃，尚未實作離線 CTN 待同步佇列。
- 已辨識為運輸框／集束的 CTN 不會被當成「未建IQC單支鋼瓶」加入。現有 IQC RT 衝突仍保留獨立錯誤，不改標未建IQC。
- 還有查詢中的 CTN 時，不能完成批次，避免漏收查詢尚未返回的資料。

## 驗證範圍

Node.js 語法檢查通過；Chromium set_content 搭配測試替身執行 23 個行為斷言通過，含正常／缺少IQC／框與集束排除／格式不完整／多RT衝突／重複／模擬交易中止／重新讀取／逾時與登入失效不假入帳／本機完成批次；320、390、430px 下紅色標記可見。

本機瀏覽器導覽受管理政策阻擋，因此 IndexedDB 採記憶體交易測試替身、IQC API 亦為模擬回應。未宣稱真實 IndexedDB、正式 IQC API 整合、iPhone 或 Honeywell 實機驗收通過。
