# 普通 0 / 斜線 0 配對測試

測試包 `CYL-ZERO-AB-1-20261025`。這是本機測試準備，不變更 DEMO 引擎或正式註冊。固定初次基準：DEMO 0.6.1，前端 main `aeee973842c69fa4fdb9829755b5a000a0cdab84`。尚無兩種寫法的原始照片，不報告辨識改善。

## 使用者需提供的資料

列印 worksheet.py 生成的三頁 A4 PDF。第 1 頁是參照，後兩頁各手寫同樣 16 組完整 CTN / 鋼號：A 頁數字 0 不畫線；B 頁只有數字 0 畫線，字母 O 均不畫線。不要只寫尾碼，不改其他字的習慣。同一人、同一支筆、相近大小與光線，各拍一張完整、清楚、正面原圖；不要截圖、加濾鏡或加系統綠格線。前 8 列先寫 A 再 B，後 8 列先寫 B 再 A，減少固定先後影響。拍前檢查是否抄錯，不把抄寫錯誤當辨識錯誤。

使用者只要回傳兩張原始相機照片並標明 A / B；CG 負責對齊、辨識與統計。編號是人工設計的測試文字，不能當作真實鋼瓶登錄。CTN 第 3、4 碼都是數字；其他位置刻意含 O / 0 / 6 / Y / R 等對照。含零與不含零的鋼號都有；鋼號樣本長度不代表系統新增固定長度規則。

## CG 執行與保存

- 原圖、草稿、逐列結果只放在 Git 排除的私人目錄，不提交公開 GitHub。
- 用同一固定版本、相同設定、乾淨瀏覽器工作階段先跑原圖自動對齊。保存未覆蓋的原圖與對齊畫面。若定位失敗，記錄失敗；人工校正後再跑的結果另標示，不能冒稱自動全流程成功。
- 先核對手寫內容是否與 cases.json 一致。若有抄寫錯誤，請重寫該組兩種版本或另外記錄；不悄悄改答案來迎合 OCR。
- 不傳 reference 值給辨識函數。第一次辨識完，在任何手改／套前綴／勾選之前匯出草稿。A、B 都保存原始選中候選，包括空值、多字、少字。不得挑第二候選充當正確，也不得挑最好的一次。
- `evaluate.cjs` 從 `sourceIndex` 對原列，固定 16 組分母，漏列算錯；拒絕人改、前綴、重複來源列、版本不一致或同一張照片重複充當兩種寫法。
- 主指標是 CTN 與鋼號同列都完全正確的組數 / 16；另報 CTN / 16、鋼號 / 16、全部欄位 / 32、含零欄位全文正確率與長度差異。不把模型信心分數或候選命中率當正確率。大小寫、全半形與空白以既有編號規則標準化，字母 O 與數字 0 保持不同。
- 結果只描述這位書寫人及這兩張照片。兩種都差時，下一步評估本機其他核心或訓練資料；不據此改現場全部寫法，不自行啟用雲端。

```sh
python tools/cylinder-zero-ab/worksheet.py --font /path/to/chinese.ttf --output /private/output/zero-ab.pdf
node tools/cylinder-zero-ab/evaluate.cjs /private/ordinary.private.json /private/slashed.private.json /private/report.private.json
node --test tests/cylinder-zero-ab.test.cjs
```

PDF 需要 ReportLab 與支援繁體中文的 TrueType 字型；Windows 可用 `C:/Windows/Fonts/msjh.ttc`。工具不含照片上傳、註冊寫入或辨識答案替換。
