# IQC RC31 — OCR-S1-20260920

入口：[`v31.html`](./v31.html)。使用現行 DS 登入，再由「更多」→「IQC 影像建檔 RC」進入。

此版本修正 RC30 的引擎啟動與照片排程，正式 IQC 寫入保持鎖定。沿用原本的照片、批次及待傳儲存空間；不清除或自動補送舊業務待傳。

## 行為

- 多張照片先依序解碼、壓縮並保存，再按「開始辨識未完成照片」。分次加入會接續同批。
- 首張直接使用初始化完成的引擎；同批及短時間後續照片共用一個引擎，沒有丟棄前兩次辨識結果的暖機步驟。
- 初始化共用一個 Promise；初始化上限 60 秒，每次辨識上限 55 秒。逾時、取消及離開前景會終止實際 Worker，舊結果不能回寫。兩分鐘閒置後釋放引擎。
- 啟動或辨識失敗會停下本輪；照片保留，可重試同一張。已完成照片不自動重跑，個別照片可按「重新辨識」；已由 Cloud 補完的結果保留。
- 本機處理期間鎖住新增、刪除及切換批次，避免資料仍在寫入時啟動辨識。支援 Web Locks 時，同時開啟的 RC31 本機操作互斥。
- Cloud 沿用原 RC API／權限設定。本版改由「補辨識缺漏（Cloud）」手動觸發，選擇一張有缺漏的照片；本機與 Cloud 不在同一頁同時改照片。未啟用時會顯示狀態。
- 「辨識紀錄」提供最近 100 個階段、耗時與固定錯誤代碼，可複製。紀錄不含帳密、照片或 CTN。各 pass 的原始 OCR 文字保存在本機照片紀錄中。

## CG 檢查

- `node --test tests/iqc-ocr-rc31.test.cjs`：10 項引擎／入口／解析回歸。
- `node tests/iqc-ocr-rc31.browser.cjs`：隔離瀏覽器、合成圖片、模擬 Google 登入與業務 API。實際從公開 CDN 載入 Tesseract 5.1.1，驗證連續三張、追加、重試、取消、重新讀回、下載失敗及手動 Cloud 契約；Cloud 辨識回應為模擬資料。
- 瀏覽器測試需 Playwright；可用 `PLAYWRIGHT_MODULE` 指定模組位置，`EDGE_EXECUTABLE` 指定 Chromium／Edge 執行檔。`DS_WEBKIT=1` 選 WebKit。
- 本機 Windows WebKit 寫入 Blob 回覆 `UnknownError: Error preparing Blob/File data to be stored in object store`；獨立三字元 Blob 也可重現，故完整 WebKit 流程未通過，不能視為 iPhone 驗證。

## 現場驗收

1. 確認頁面為 **RC31 / OCR-S1-20260920**，以 DS 帳號登入並進入影像頁。
2. 用一張實際 Honeywell 照片按「開始辨識未完成照片」。預期第一張就進入處理並產生結果或明確錯誤，不需先上傳兩張暖機。
3. 再加入另外兩張／或另開新批一次選三張。預期依照片順序完成；已完成照片保留，未完成照片可重試。
4. 辨識中按「停止本輪辨識」，再按開始。預期照片不消失、不重複加入、舊工作不蓋掉新结果。收回前景後仍需依 DS 規則重新驗證登入。
5. 逐筆對照照片的 RT、狀態、廠區、總量及 CTN。數量吻合並不代表每個字元正確。若有缺漏，可手動補辨識；本輪不測正式 IQC 建檔。
6. 若卡住或失敗，展開「辨識紀錄」→「複製辨識紀錄」，並告知第幾張與實際現象；不需重掃或清除網站資料。

## 實際限制

這版以啟動穩定性為主，沿用 RC30 辨識及合併規則。合成續頁測試曾把 `UV90WXY` 誤讀為 `UV00WXY`；需要人工逐字複查，不能聲稱辨識率已達標。尚未使用現場原始照片、實體 iPhone、現場弱網或真實 Cloud OCR 驗收。首次核心／模型下載仍需要網路；本機「已保存」僅代表目前浏览器儲存成功。

引擎生命週期依 [Tesseract 5.1.1 createWorker 原碼](https://github.com/naptha/tesseract.js/blob/v5.1.1/src/createWorker.js) 核對；固定版本的原生 Worker 在 `createWorker` 返回 Promise 前建立，因此可於初始化未完成時立即終止。本次未修改 Apps Script、正式模組或客戶 API。
