# IQC RC31.1 — OCR-S2-20260921

入口：[`v31.html`](./v31.html)。使用現行 DS 登入，再由「更多」→「IQC 影像建檔 RC」進入。沿用原 RC31 網址與本機照片、批次，正式 IQC 寫入保持鎖定；不自動補送舊業務待傳。本次未修改 Apps Script、正式模組或客戶 API。

## 本輪修正

- 唯讀保護每 80 ms 重寫同一按鈕文字，會再次觸發自己的 DOM 監聽；原 RC31 的 100 ms 延後更新可能一直被取消。改為文字不同才寫入，並讓照片按鈕在實際渲染後立即安裝，持續 DOM 變動也不再無限延後。
- 保存／整理照片時仍接受開始操作，合併為一個等待中的辨識工作；保存完成才開始。辨識中重複點擊只提示進度，不重複啟動。取消或保存失敗會取消排程，顯示明確狀態。
- 觸控完成有效點按時直接處理開始操作，排除滑動、取消及後續相容 click 的重複觸發。辨識紀錄新增開始點按與排程階段。
- 單張無文字或個別辨識失敗會保留照片、標示錯誤，再處理下一張；引擎初始化、儲存失敗或使用者取消才停止整批。已完成照片不自動重跑。
- 保留照片開頭沒有 RT 標題的 CTN，即使同張後段辨識到另一組 RT。續頁不再依前一組數量猜歸屬或截掉超出數量的 CTN；不能確認歸屬的候選顯示「待歸類」。
- 照片儲存／讀回加入 15 秒上限及明確錯誤；介面更新不再把已結束的工作一直標成忙碌。

以上是原碼與可重現測試確認的缺陷，尚不能斷言已涵蓋現場「第三張才成功」的全部原因。

## 手動歸類與複查

每張照片可開啟「手動歸類／核對 CTN」。預設勾選整張候選，也可只勾選個別 CTN；選擇既有群組或輸入 RT、狀態、廠區及預期總量，再套用。CTN 可逐字修正，同張混合不同 RT 時分次套用所選 CTN。

- 原始 OCR 文字不變；人工結果、來源照片及修改歷程分開保存，重新載入仍可讀回。
- 「取消所選人工設定」只取消目前勾選 CTN 的人工設定，其餘保留。
- 相容讀取前版 V8 人工核對內容，不清除舊資料。重新辨識漏掉已人工核對的候選時仍保留，並提示需要重新確認。
- 重複 CTN、缺 RT／狀態／廠區、數量不一致及過期人工結果都會標示。畫面區分「讀到候選」「待歸類」與「數量吻合」，後者不代表字元正確。
- 本 RC 的手動 RT 僅檢查輸入格式，沒有即時 RT 主檔驗證；歸類供複查，不能視為正式入帳或後端確認。

## 執行與診斷

沿用 RC31 的共用引擎、60 秒初始化上限、每次辨識 55 秒及兩分鐘閒置釋放。逾時、取消或離開前景會終止實際 Worker，舊結果不能回寫。回前景仍遵守 DS 重新驗證規則。

Cloud 沿用原 RC API／權限，僅由「補辨識缺漏（Cloud）」手動選擇一張照片觸發；本機與 Cloud 不同時修改照片。未啟用時顯示狀態。

「辨識紀錄」保留最近 100 個階段、耗時及固定錯誤代碼，不含帳密、照片或 CTN。各 pass 的 OCR 文字另外保存在本機照片紀錄。

## 現場驗收

1. 確認 **RC31.1 / OCR-S2-20260921**。加入一張實際照片，按一次開始；保存中顯示已排定，完成後進入辨識，或給出明確錯誤。不要清除網站資料。
2. 一次三張，再試首張後追加兩張。每張應有各自結果或錯誤，已完成照片保留。單張無內容不應阻止後面的照片，RT 沒拍到的候選應進待歸類。
3. 在缺 RT 照片開啟人工複查，套用整張至正確群組；再只選一個 CTN 分至另一 RT。預期未選項目不變，逐字修改與重新載入後仍保留，原 OCR 文字未覆寫。
4. 依照片核對 RT、狀態、廠區、數量和 CTN；如需重辨識／取消人工設定，只處理選定照片或 CTN。本輪不測正式建檔。
5. 若開始沒有反應或某張失敗，複製「辨識紀錄」，附第幾張、一次加入或追加、期間是否切到背景，供定位同一次工作。

## 尚待驗證與限制

本輪尚未收到發生問題的原始照片或新版辨識紀錄；現場原照片、實體 iPhone、弱網與真實 Cloud 辨識仍待驗收。合成測試仍可把 `UV90WXY` 誤讀為 `UV00WXY`，因此未宣稱辨識率達標。首次下載核心／模型仍需網路；本機已保存僅代表當前瀏覽器儲存成功。
