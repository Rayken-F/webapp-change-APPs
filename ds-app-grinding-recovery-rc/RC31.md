# IQC 影像 RC31.12 / OCR-S13-20260924

## RC31.12：移除批次與空批次檢查

本輪與 RC31.11 成功提示合併驗收；不另要求重做已通過的多批辨識、去重與字元條列。

- 批次資訊新增「移除目前批次」。確認視窗會顯示名稱、照片張數及刪除範圍。取消不變；確認後，同一 IndexedDB 交易刪除该批的批次紀錄、原圖／縮圖位元、OCR 及人工歸類，交易失敗全部回復。其他批次不動，接著選取剩餘批次。
- 已有待傳、傳送中、已同步收據或非草稿狀態的批次不能移除。確認後到實際刪除間再核對來源版本及送出紀錄，避免另一分頁更新後被誤刪；遲到的照片／批次更新不能重建已移除的批次。
- 移除最後一批後呈現「目前沒有批次」，重開仍保持，不自動持久化新的空批次；按「＋新批次」或實際加入照片才建立。
- 空批次在選單明確標示。步驟 3 的「送出前檢查空批次」只讀本機，回報有 CTN、空批與需處理批次。空批排除、不建立待傳資料；有照片但沒有 CTN 的批次保留並阻擋，不當空批略過。這項是空批檢查，不代表 RT／數量／權限等完整送出驗證已通過。
- RC31.11 的「歸類保存成功」小型提示保留，交易成功後出現，約 2.5 秒自動消失。
- 該批舊人工設定及輔助辨識暫存也會清除；輔助工作紀錄為另一資料庫，主批／照片交易成功後才清除。若輔助清理失敗，畫面會明確說明照片已移除、輔助紀錄未清理，不誤稱整批未刪除。這些輔助紀錄不包含原照片。

正式 IQC 寫入維持鎖定，沒有排送或改動後端資料。第二階段資料落點仍待使用者選擇；後續接線需在建立待傳前重新呼叫空批檢查，不沿用過期的預檢結果。Google 後端、正式 OQC／Grinding／日報及登入未改。

合併驗收（原入口重整至 RC31.12，用可刪除的測試批次）：

1. 手動歸類 → 套用歸類：保存成功後出現小提示，約 2.5 秒消失。
2. 建立空白測試批次：選單標示「空批次」；到步驟 3 按「送出前檢查空批次」，應提示排除空批，沒有送出或新增待傳。
3. 對測試批次按移除並先取消：資料保留。再確認移除：批次、照片及歸類一起消失，其餘批次仍在。已有待傳／收據的批次不應被移除。
4. 若只剩可刪除的測試批次，移除最後一批並重整：不另生空批；新增批次／加入照片仍可繼續。無須為此刪除正在使用的資料。
5. 有照片但未辨識的測試批，預檢應提示先辨識／校對，不能顯示成空批排除。

## 最短驗收

前置：重整固定 RC，更多 → Honeywell 影像，確認 **RC31.10 / OCR-S11-20260924**。用現有照片，不清網站資料。

1. 批次資訊 → 命名此批次為「框架 A」，按「儲存名稱」。按「＋新批次」建立 B，各放各框的照片，區域可分別選。互切時，照片、序號、區域及已保存的 RT／CTN 應各自正確；重整後仍可切回 A。辨識 A 不應改動 B，辨識中切換選單暫停使用。
2. 一批用現場 3～4 張照片按一次「開始辨識未完成照片」，應逐張完成。這是新批次隔離的必要回歸，不要求重做已通過的三輪啟動測試。
3. 手動歸類 → 套用歸類：頂欄先顯示保存中，完成顯示已保存；關閉編輯後，其他照片及下方群組的手動按鈕應可使用。若失敗，應提示未保存、可重試，不能一直停用。保存後重整，確認 RT／CTN 修改仍在。
4. 開啟「查看需核對字元」：每筆 CTN 提醒各占一個條列項目，可查看原照片。
5. 同批放入有重疊 CTN 的照片：結果清單同一 CTN 只列一次，顯示重複數量。若刻意指定不同 RT／狀態／廠區，應集中顯示衝突，仍可回到各張照片核對；不得自動選定一個 RT。

「資料保留」指照片、辨識結果及按過套用歸類的修改在切批／重整後仍在；如果照片消失、已保存的 RT 恢復空白或寫到別批，即為失敗。編輯表單尚未按套用的修改，在切批時會先詢問是否離開。

有問題：頂欄「進度／操作」→「複製辨識紀錄」，並說明批次、按鈕與畫面；不需連按或清網站資料。
