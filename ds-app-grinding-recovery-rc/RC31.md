# IQC RC31.2 — OCR-S3-20260921

入口：[`v31.html`](./v31.html)。現行 DS 登入 →「更多」→「IQC 影像建檔 RC」。沿用 RC31 固定網址與本機照片、批次；正式 IQC 寫入保持鎖定，不自動補送舊業務待傳。此次沒有 Apps Script、正式模組、客戶 API 或權限變更。

## 本輪修正

- 相簿按鈕旁增加「開始辨識未完成照片」及即時進度。上方、原下方與單張重試共用操作；照片保存中點一次會排定，保存完成自動開始。
- 處理有效觸控的 pointerup；手指未移動但版面微捲動時不再丟棄操作，同一次相容 click 不重複觸發。滑動取消不啟動。未變動的照片卡不再被定時刷新重建。
- 辨識到一般文字但 0 個 CTN 不再算已完成。保留原文、標示需人工複查，下次開始仍會重試。無 RT／狀態的 CTN 保留待歸類。
- 一般辨識未找到 CTN 時，額外定位照片中的淺色螢幕區域，避開深色機身，再作有限次補辨識。無法保證反光、斜拍、截斷與字元誤讀全部修正。
- 所有照片均可進入「手動歸類／核對 CTN」，包括 0 候選。可補登漏讀 CTN，查看各次原始 OCR 文字；原照片與 OCR 保留，人工設定另存，重新辨識與重整不清除。
- 同 RT 的續頁缺狀態／廠區時，僅在有唯一相容群組時補齊並合併；相同 CTN 去重、保留每張來源。明確不同狀態／廠區或歸屬不唯一仍分開並提示。
- 群組顯示去重數量、重疊筆數與參考總量差額。16／18 支是框架容量，不當作本批實際總量；同 RT 可跨多框，本版沒有新增框架容量或按框阻擋規則。
- 本 RC 照片縮圖的 Blob URL 保留至卡片移除，修正載入後立即撤銷造成預覽失效。舊版記憶體處理保持原行為。
- 一次開始內，辨識核心下載／啟動暫時失敗自動重試一次；逾時、取消或辨識內容錯誤不無限重試。持續失敗仍顯示錯誤、保留照片供重試。

以上是原碼與測試確認的問題；尚不能斷言已涵蓋現場按鈕啟動失敗的全部原因。

## 多張處理與數量核對

可一次多選照片，由單一辨識引擎逐張處理；完成一張就保存一張，不同時執行 30 個辨識工作。個別無文字照片保留失敗狀態並繼續後續照片。初始化逾時、儲存失敗與取消會停止本輪；回來後按開始處理未完成照片。切到背景仍停止並保留已存結果，不保證 iOS 背景運行。

本輪已完成 30 張合成照片的一次加入、一次開始、逐張保存與重整讀回測試；尚未完成原 iPhone 20～30 張實拍照片的穩定性、記憶體及精準度驗收。首次核心／模型下載仍依賴網路；外部服務中斷可能需要重試。

PACT／Honeywell 照片可能只是同一框的分頁，也可能屬於不同框。同 RT 分組是整理候選，不能代表一個實體框。數量欄目前是 RT／狀態／廠區參考總量，未知可留空；不可因框架容量為 16／18 就直接填成實際數量。按框核對實際支數的操作設計尚未實作；本 RC 仍不允許正式送出。數量吻合不代表 CTN 字元正確。

## 手動歸類

每張照片開啟「手動歸類／核對 CTN」。選既有群組，或輸入 RT、狀態、廠區及參考總量；整張或只勾選指定 CTN 套用。缺 RT 的續頁可只填 RT，在唯一相容群組下合併；有歸屬衝突時需明確填寫。

「漏讀的 CTN」每行一個完整 CTN；已列出的不重填。補登仍須人工對照照片。格式錯誤、同張重複或跨群組衝突會提示；原始 OCR 文字不覆寫。取消所選人工設定只作用於所選項目，舊 V8 人工資料相容讀取。

手動 RT 只檢查格式，沒有即時 RT 主檔驗證；不能視為正式入帳或後端確認。Cloud 沿用既有 RC API，只由「補辨識缺漏（Cloud）」手動觸發，本輪測試的 Cloud 回應為模擬。

## 現場驗收

1. 確認 **RC31.2 / OCR-S3-20260921**。進原 RC 批次，先加入一張，再追加兩張；於相簿旁按一次開始。應立即顯示準備／排定，逐張顯示結果或明確錯誤，已完成照片不重跑。不要清除網站資料。
2. 對缺 RT／狀態照片辨識。讀到的 CTN 應留在待歸類；0 候選仍可開人工核對及補登。原文可展開查看，照片保留。
3. 將相同 RT 的續頁套用至同一群組。若只有一組狀態／廠區，單填 RT 可合併，來源照片保留、重疊 CTN 只算一次；明確不同狀態／廠區不應強行合併。重整後設定仍在。
4. 先用 5 張確認，再增加至 10、20～30 張。保持頁面前景；檢查照片總數、每張結果、最後一張及重整讀回。這是現場待驗收，不是已保證 30 張成功率。
5. 本輪不提交正式 IQC。若按鈕仍無反應，複製「辨識紀錄」，提供第幾張、一次加入或追加、是否切背景。紀錄限最近 100 個階段，不含帳密／照片／CTN；各次 OCR 文字另存於照片本機紀錄。
