# RC v11 — 2026-08-23

Status: FIELD TEST REQUIRED. Do not promote to formal DS.

## Goals
1. Stop recurring iOS black blank area when switching Dashboard / Daily Report / Grinding WIP.
2. Preserve the LINE-like floating bottom navigation without allowing it to participate in iframe/module height calculations.
3. Show the full `Grinding WIP` label instead of ellipsis clipping.
4. Improve fixed multi-photo Honeywell OCR reliability where single-photo OCR is stable but 3-photo batches frequently fail.

## Structural shell/navigation change
- `rc-line-nav-v8.css` is now pure overlay navigation.
- Module mode no longer reserves bottom space for the nav: `.app-shell.module-mode .main-view { bottom:0; }`.
- `rc-shell-stability-v9.css` forces module shell/main/host/iframe to fill the full viewport (`inset:0`, `height:100%/100dvh`).
- `rc-shell-stability-v9.js` only stabilizes login/home. It intentionally does not write module viewport variables or call RC v3 geometry resync/repatch while in module mode.
- `Grinding WIP` receives a smaller dedicated label font instead of ellipsis.

Rationale: the previous design reserved a calculated bottom region for the floating nav. iOS viewport changes could make that reserved region incorrect, producing the persistent black gap. v11 removes the reserved region from module geometry entirely; the nav floats above module content.

Known tradeoff: because the nav is a true overlay, it can visually cover the very bottom of a module. If a real module action is obstructed, fix that module's own content padding/safe-area rather than reintroducing shell-level reserved height.

## Multi-photo OCR change
- `iqc-ocr-multipass-hook-rc-v3.js` now implements isolated OCR workers per photo.
- Each image is serialized; no concurrent photo recognition.
- A fresh native Tesseract Worker is created for each photo, with 45s init timeout and 55s recognition timeout.
- Worker is terminated immediately after that photo completes/fails.
- Each photo gets at most one supplemental recognition pass, only for low-confidence/empty-output cases.
- Each photo gets one automatic retry with a fresh worker.
- Existing `RT + status + plant` cross-photo grouping remains unchanged.

Rationale: field tests showed single-photo recognition stable while identical 3-photo batches succeeded only 1/5 times, suggesting iOS WASM Worker state/memory accumulation rather than image content variance.

## Field acceptance checks
- Repeatedly switch: Home → Daily → Dashboard → Grinding → Daily → Home. No black blank strip should appear.
- Bottom nav must remain visible when appropriate and `Grinding WIP` must be readable in full.
- Run the same fixed 3 Honeywell photos at least 3 times. All photos should process sequentially without an initialization lock/hang. Existing correct same-RT cross-page merge must remain intact.
