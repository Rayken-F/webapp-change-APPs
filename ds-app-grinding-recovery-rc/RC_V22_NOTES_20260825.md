# IQC Hybrid Image RC v22 — Isolated Local OCR

Date: 2026-08-25

## Purpose
Fix multi-photo Local OCR instability on iPhone/PWA by removing the shared native Tesseract worker used across a batch.

## Changes
- Replace `iqc-ocr-batch-stable-v14.js` in the RC entry with `iqc-ocr-isolated-v22.js`.
- One native Tesseract worker per photo.
- Worker is terminated after every photo, followed by a short cooldown.
- Maximum two OCR passes per photo: primary + optional Sparse Text fallback.
- Remove the third high-contrast OCR pass from the active RC path to reduce memory pressure.
- Add an 85-second hard limit for one photo task.
- A Local OCR failure returns a synthetic failed result so the batch can continue to the next photo instead of aborting the entire batch.
- V21 Selective Cloud Escalation remains active; a failed/empty Local photo becomes an AI candidate while completed Local photos remain reusable.

## Acceptance test
Use the same three Honeywell photos that were unstable in multi-photo mode.

PASS criteria:
1. All three photos are processed sequentially without the batch remaining permanently in `辨識中`.
2. A failed Local photo does not prevent later photos from being processed.
3. Local-complete photos remain available to V21 and are not needlessly re-sent to Cloud.
4. `AI待辨識` is limited to the minimum necessary photo(s), normally 0 or 1 for the known three-photo case.
5. No result-card/UI flicker regression.
