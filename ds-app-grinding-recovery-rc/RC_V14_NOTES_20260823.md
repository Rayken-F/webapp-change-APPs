# RC v14 — 2026-08-23

Status: TESTING ONLY. Do not promote before field PASS.

## Scope
Only IQC Honeywell OCR runtime stability and image-memory cleanup were changed. The RC v12 module navigation fix remains frozen and unchanged.

## Field finding before v14
- OCR recognition quality/recall is now correct when the engine completes successfully.
- Fixed 3-photo batch success rate in v13 was only 2/5.
- v13 created/terminated a warmup Worker plus a new Worker per photo, causing at least 4 WASM Worker initializations for a 3-photo batch.
- Repeated UI rendering also created thumbnail Blob URLs without explicit revoke.

## v14 design
- One native Tesseract Worker is shared sequentially inside one batch.
- No parallel OCR.
- Primary + Sparse + high-contrast passes are preserved so recognition recall does not regress.
- Worker is recreated only after actual failure or after 4 processed photos.
- Worker auto-terminates after 6 seconds idle, on page background, panel close, or new batch.
- If a Worker fails, discard it, wait 0.9s, recreate once, and retry only the failed photo.
- Batch rerun cooldown: 3 seconds.
- Thumbnail Blob URLs are revoked after image load to prevent repeated-render memory retention.
- IndexedDB remains the durable weak-network store and is not cleared by RAM cleanup.

## Headerless continuation
Existing meta-grouping already supports a strict continuation rule: leading CTNs on the next ordered photo may attach to the immediately previous incomplete group. It does not guess when the previous group is already complete or when ownership conflicts exist.
