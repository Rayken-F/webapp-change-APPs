# DS 工作台 AUTH-K4 / LAYOUT-K4

使用者的 AUTH-K3 恢復驗證紀錄為總耗時 11.354 秒、伺服器驗證 1.195 秒、收到後套用畫面 4 毫秒。主要等待在驗證計時以外；不能由 Wi-Fi 訊號或頻段推定原因，也不能把這筆恢復驗證當成全部帳密登入成績。

AUTH-K4 在登入頁準備可重用的 Google HtmlService RPC 通道，後續登入及回前景驗證可省去每次 ContentService 的轉址回傳。新通道未就緒或無法回覆探測時，在送帳密之前使用原 HTTP 路徑；已送出的 RPC 不會自動重送密碼。維持即時 active／權限核對、簽章／到期、錯誤鎖定、稽核、15 秒提醒、45 秒等待上限與取消功能。通道中斷後重新準備連線，不保存額外登入憑證。診斷增加 transport、bridge 狀態及計時，仍不含帳密／token。

LAYOUT-K4 由工作台統一保留底部功能欄空間，適用一般長頁、內部捲動區、IQC 抽屜及跨來源 Dashboard。鍵盤開關不再改動模組預留高度，避免每次輸入重排；子頁不再重複加上功能欄高度。功能欄依可視視窗定位，公佈欄短內容與載入後長內容共用位置。修正 Dashboard 回覆 ACK 後再回覆造成的訊息循環。

## 發布後驗收

固定入口 `/webapp-change-APPs/ds-app/`，登入頁顯示 `AUTH-K4 / LAYOUT-K4`。保留原網站資料，重新開啟／重整取得新版。

1. 正常登入後登出，再登入 2～3 次。應避免之前連續卡 15～25 秒的情況；記錄實際秒數。若仍慢，在登入頁展開「登入連線資訊」→「複製連線紀錄」貼給 CG，依 transport 與 server 分段判斷，不能預先視為效能驗收通過。
2. 公佈欄：觀察資料載入前後，功能欄應留在底部，不隨需求清單出現而跳動。
3. 日報、Grinding WIP、Dashboard 逐一捲到最底，最後的按鈕／紀錄應能完整顯示在功能欄上方。IQC → 異常 → 抽屜底部的「建立異常單」應完整可见；只需檢查位置，不用建立假單。OQC 共用工作台容器，也確認底部內容可看見即可，不必重做掃描與 RT 全套。
4. 日報原集束備註輸入數個中文字，確認輸入框不逐字往上跳，收起鍵盤後功能欄回到原位。
5. 回前景是指登入後切到其他 App 約 5～10 秒再返回：仍須驗證，成功後回到原模組且保留尚未送出的同帳號表單。此項可在正常使用時確認，不需再刻意跑五輪。

手機中文輸入法、iOS 公佈欄空白與真實帳密連續登入仍待使用者驗收。首次通道準備、Google 排程、後端讀寫及弱網仍可能等待；通道未就緒時可走原 HTTP，因此不宣稱根除所有延遲。原 OQC 後端、資料、權限與 RT 加速邏輯沒有更改。
