# DS workstation AUTH-K2 / keyboard K2

Status: implementation and 38 automated checks completed; deployment evidence is recorded separately. iPhone keyboard and real weak-network timing acceptance remain pending.

- The keyboard keeper now reads the production viewport state and detects editable controls inside the active iframe. It no longer clears the keyboard class while typing. Shell inset updates avoid repeated identical layout writes and honor the child-focus guard.
- Remove IQC's independent credential form, login handlers and module logout. IQC bootstrap reads the current parent session; business requests continue through the original IQC backend. Network failures do not delete the shared session. Notification refreshes coalesce and pause when hidden.
- The workstation calls the original IQC auth endpoint directly for workstation_login/workstation_bootstrap, receiving verified identity and current checkbox permissions in one backend invocation. The Portal home/priority API remains unchanged. The backend reuses existing password hashing, signed token expiry, failure counters, audit and module authorization. No TTL extension or offline authentication is introduced.
- New workstation login attempts fail with AUTH_BUSY if the existing script lock cannot be acquired in 1.5 seconds, instead of queueing for 30 seconds. Legacy callers retain their behavior. Account failure counters do not change on lock contention.
- Foreground restoration still validates the session and fresh permissions on the server. Overlapping restore/login triggers share one request; 15 seconds bounds network and response-body waiting. A failed network check stays locked and exposes retry while preserving the token. Explicit invalidation clears it. Logout generations reject late replies. Successful same-account restoration preserves module forms; permission revocation removes the affected frame.
- Login no longer preloads daily and Grinding modules in the background. Modules load when selected. IQC RT1 and OQC V1.0.1 business rules are preserved.

Validation: 7 backend auth tests, 12 shell/auth/keyboard tests, 10 IQC transaction regression tests, 4 IQC selection tests, 5 OQC production tests. A local browser fixture checks the actual shell and IQC UI with synthetic credentials and responses; no live account or business data is used.

Acceptance: original workstation URL; confirm AUTH-K2. In the same iPhone PWA daily bundle note, type continuously with the Chinese IME, delete, switch fields and close keyboard; verify no progressive upward movement and navigation returns afterward. Open IQC and switch/return from background: no IQC credential form. Enter/restore the workstation using the real account and briefly switch background/foreground; fresh validation must still happen without overlapping login loops. On weak network a timeout should offer retry, never grant unverified access. Verify one ordinary allowed module entry and a disabled permission remains unavailable. Report real timing separately; no fixed successful-login latency is promised.
