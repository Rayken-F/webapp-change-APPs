# 公佈欄 RT 排程 P1

版本：RT-SCHEDULE-P1-20261004。狀態：候選已實作及本機驗證，尚未正式部署。

廠區分類為 7201 竹北、7209 台中、7973 桃園、7A39 安南與 Other。每個廠區依緊急、中等、暫緩、常態排序；同優先順序先列集束，按瓶數、容量遞增，再列散支容量遞增。Excel 未完成量沿用原欄位，集束以框、散支以支顯示，不混用換算後的 ea 欄。無法辨識規格的資料保留並標示單位待確認。

後端匯入成功後提供選定欄位與進度備註。來源 Excel 的同 RT 多需求列保留；預設以 Excel 取代相同 RT／廠區的手動顯示資料，其餘手動需求保留，不修改原始手動主檔。匯入資料不提供手動編輯按鈕。

長按卡片約半秒、鍵盤 Enter／Space，或按有備註卡片的「備註」可查看純文字內容；短按、滑動與取消手勢不開啟。關閉返回原捲動位置。備註視窗高於底部導覽列，低於登入鎖定畫面。

「重新整理」僅在後端已啟用郵件匯入、且使用者原有生產需求編輯權限時要求讀信；其他使用者只讀最後成功排程。讀信最長等待 35 秒後再讀取最新已保存資料。等待逾時不等於取消伺服器作業，也不清空舊資料。

驗收位置：原工作台 → 公佈欄。正式發布後才要求現場驗收：

1. 確認來源日期與收到的最新 Excel 日期相符。
2. 逐一選取五個廠區，確認廠區與優先順序、集束／散支規格順序。
3. 對照一筆集束和一筆散支的「未完成量」與單位。
4. 長按有備註的小卡，確認文字；關閉後仍在原位置。正常上下滑動不應彈出備註。
5. 有編輯權限的帳號重新整理兩次，資料不重複；未開放編輯權限者仍可讀排程與備註。
6. 既有手動新增、編輯及封存流程只驗收實際需要的需求，不要求重跑其他模組。

本機檢查：14 項後端解析／儲存／權限測試、6 項排序／長按測試及39 項既有登入／工作階段回歸測試，共59 項。另以本機 Browser 驗證真實 shell 資源的篩選、備註、返回捲動位置、遮擋與失敗保留資料。Google 執行環境、正式收件排程及 iPhone 手勢尚待啟用後驗證。

發布前須取得本次正式發布同意並完成部署擁有者的 Gmail 唯讀授權／Gmail API 檢查，再發布同一原網址的 Portal、IQC 讀取服務及前端。每日更新候選使用台灣時間07:00～08:00；頻率仍待確認。沒有更改固定網址、其他模組、權限名單或任何業務資料。
