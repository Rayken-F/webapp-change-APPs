# AUTH-K5 / LAYOUT-K5

K4 現場回報登入速度改善，但失敗時等待視窗會關閉，錯誤訊息落在登入表單下方。K5 改為持續顯示中央錯誤視窗，需按「返回登入」關閉。Google RPC 通道失效時重建連線供下一次明確操作使用，不自動重送帳密；連線紀錄補入固定錯誤代碼、回應來源與 HTTP 狀態，不保存原始錯誤文字、帳密或 token。等待期間其他操作完成不能收掉登入遮罩。

使用者不接受 K4 的模組底部保留區。K5 恢復與公佈欄一致的懸浮膠囊導覽，iframe 延伸到螢幕底部；頁尾與抽屜內保留可捲動距離，使最後按鈕能露出。輸入期間不縮放模組或逐字調整底部距離。保留已通過的公佈欄定位與背景恢復驗證。

Dashboard 的 Google HtmlService 另有一層 sandbox，舊接收器只對直接 parent 傳訊；其 body 的 0px 宣告又覆蓋 root 高度，另有兩個 calc 拼字錯誤。Dashboard 原部署已更新第 137 版，工作台辨識所屬 sandbox 的 READY/ACK，讓內容延伸至膠囊後方並能完整捲到底。27 檔 Google 原碼讀回一致，僅修改 AP_index_v2 接收器；原編輯器縮排保留，其他日報部署及固定網址維持。發布證據見前端 PR #9、私人後端 PR #12。

## 已完成檢查

- 40 項前端登入／取消／重試／IQC 選取與 OQC 回歸測試。
- 20 項隔離瀏覽器檢查，包含持續錯誤視窗、明確重試、無底部保留帶、最後按鈕可見、輸入幾何不變、實際 IQC 抽屜、巢狀跨來源 Dashboard 接收器及 body 高度繼承。
- 現行登入 Google v19 九檔與 HEAD、已發布 K4 原碼相符，沒有部署漂移；本候選未改登入後端。
- Dashboard 32 項原碼核對通過；私人 GitHub 保存第 136 版、原草稿及第 137 版原碼。既有 Config API_TOKEN 以佔位符排除，精確原檔只保留本機，線上值未修改；不可直接將含佔位符的備份上傳。
- 已用本機 K5 工作台／合成登入連接真實 Google Dashboard；確認其實際有兩層 sandbox，補上受限的後代視窗辨識，並納入瀏覽器回歸。線上 receiver、82px inset 繼承、92px 內容尾距及全高懸浮檢查通過；這不是實際帳號登入驗收。
- 沒有使用真實帳密或寫入業務資料。iPhone 中文輸入法、真實連續登入及整體樣式仍待候選發布後驗收。

## 發布後才進行的驗收

固定工作台入口 `/webapp-change-APPs/ds-app/`，版號需為 `AUTH-K5 / LAYOUT-K5`；前端 PR 合併、Pages 成功且線上資源核對後才開始驗收，不清除網站資料。

1. 正常登入／登出再登入 2～3 次。成功直接進工作台；失敗應保留中央原因與「返回登入」，不應無聲消失。若再失敗，截圖中央代碼或複製連線紀錄即可，不提供帳密。
2. 日報、Dashboard、Grinding、OQC、IQC 異常抽屜：滑動中內容延伸到膠囊後方，左右與下方維持模組背景，沒有橫跨整頁的固定空白底帶；捲到底，最後按鈕／最後一列能完整到達功能欄上方。只檢查位置，不建立假單。
3. 日報原集束備註輸入中文字：功能欄暫時隱藏，輸入不逐字上移；收起鍵盤後回到原懸浮位置。

K4 提供的三笔錯誤紀錄沒有錯誤代碼或伺服器計時，不能判定都是密碼、鎖、Google 平台或網路問題。本候選改善失敗呈現與通道重建，不宣稱已根除所有真實登入失敗。已通過的公佈欄載入位置及回前景項目保留，不要求整套重測。
