這是獨立、單張紙本的流程 DEMO，不是正式註冊服務。沒有登入正式系統、呼叫業務 API、更新 IQC 或寫入註冊資料庫。沒有雲端辨識功能；照片及草稿保存在此瀏覽器專用 IndexedDB，使用者可匯出／匯入 JSON 備份。原始測試照片與實際候選結果不在公開儲存庫。

## 操作

1. 選擇 JPEG／PNG／WebP 紙本照片（20 MB 以下）。
2. 載入照片後，自動在本機尋找這款四欄紙本的格線（RT／CTN／鋼號／其他），預設 16 列。找到時核對預覽後按「確認對齊」。找不到時只需調整 CTN＋鋼號資料區四角，再切換「拉正格線」，系統會一次搜尋全部內部橫線與欄界；也可按「自動貼齊格線」重試。未找到的線保留原位置並以黃色圓點提示，不冒稱全部對齊。資料列數不同時，先關閉預覽、改列數，再重新自動對齊。
3. 按「建立校對列」。每張最多 60 列，保持由上到下的來源列對應。
4. 可直接輸入，或按「試辨識未修改的列」。放大原列核對完整 CTN 與鋼號；手動補列處理漏列。OCR 不覆蓋人工修改或已核對的值。
5. 舊紙本只填尾碼時，由人員填寫共用前綴後按「確認並補全尾碼」。只處理 CTN 尾 3 碼與鋼號尾 6 碼，完整值不重複補全，變更列須重新核對。
6. 在核對區頂端填寫本批 RT（最多 30 碼英數字／連字號，不猜補、不查正式 RT 主檔）。黃色背景代表模型分數不足、候選衝突、待核對字形或格式問題；沒有黃底也必須逐列核對。空值、非 7 碼 CTN、異常字元、重複 CTN／鋼號阻擋下一步。
7. 全列人工勾選後按「開始／繼續逐支註冊」。RT 及其 Code 128 一維碼固定在上方，每次只顯示當支 CTN／鋼號及各自條碼。左下「完成註冊」保存本機確認並前進下一支；右下「人工即時修改」打字時立即更新有效條碼，改好須按「確認修改與配對」。無效／重複編號隱藏當支條碼並阻擋完成；防止快速連點跳過下一支。
8. 可以用上一支／下一支查看；重整或匯入本版草稿後繼續第一支未完成項目。修改 RT 會取消整批完成紀錄；改 CTN／鋼號、前綴或裁圖會取消相關確認與完成狀態。進度綁定實際 RT＋CTN＋鋼號，未連接任何正式註冊 API。
9. 全部完成本機確認後，才可輸出暫定 checklist（RT、CTN、鋼號、紙本列、本機確認時間）。正式 checklist 範本由使用者下一階段提供，本版不擅自定稿。CSV 匯入 Excel 時選文字欄，避免前導 0 被轉為數字。

## 斜線 0 寫法

- CTN 及鋼號均支援：數字 0 畫完整圓圈及穿越圈內的斜線，字母 O 不畫斜線。模型權重未重新訓練；本版加入本機字形判斷。
- 依同一圓圈被穿線分成左右空隙，或粗筆穿線同時延伸至圓圈兩端的證據，對應 OCR 字元位置；近直線的穿線也適用。自 0.6 起，CTC 位置找不到唯一對應字元時不直接插入 0，避免多補一碼；另排除兩個相連 9 的假雙孔。
- 有斜線 0 證據的藍筆鋼號，依實際寬空隙分段複核；保留原圖候選，另在推論副本將已定位的 0 圓圈標準化供兩模型讀取。原圖與校對圖不改動。若原圖已讀到該 0，保留相鄰原字元，避免標準化副本連帶把 7 改 1。沒有依樣本列號、固定前綴或固定答案替換。
- 兩個字元黏連、格線穿越、圓圈未閉合、斜線過淡／填滿圓圈、嚴重模糊或傾斜都可能漏判或誤判。合成測試不代表任意筆跡保證。
- 模型仍可能把沒有斜線的 O 讀成 0；未找到斜線證據的 0 會另提示核對 O／0，不強行改成 O，以保留舊紙本普通 0。此限制在合成鋼號測試仍可重現，尚未完全解決 O／0 的所有情況。

## 辨識界線

- DEMO 0.1 的 Tesseract 印刷引擎已由使用者回報辨識驗收失敗。自 DEMO 0.2 起改用支援英文手寫的 PaddleOCR `en_PP-OCRv5_mobile_rec`，不再載入 IQC 的辨識核心；正式 IQC 原碼不變。
- 原圖與藍筆去除格線／相鄰列碎筆後各辨識一次，保留不同候選。格式相符優先，其次採有斜線字形證據的候選，再依模型分數排序；分數不是正確率，兩次相同也不能視為正確。黑筆僅走原圖，仍待不同紙本測試。
- DEMO 0.4 針對 Y 被讀成 R：以藍筆去線影像二值化，再用半徑 1／2 像素的圓形範圍輕微加粗，各重新辨識一次。兩次同字數且整段結果一致、平均模型分數皆至少 0.65，差異只有 R → Y，才更新候選。沒有依列號、前綴或固定答案替換。
- 針對 0 被讀成 6：增加官方 `PP-OCRv6_small_rec_onnx` 本機複核模型，對含 6 的候選重讀原圖與去線圖；黑筆用原圖及加白邊圖。兩次同字數且結果一致、分數皆至少 0.9，差異只有 6 → 0，才更新候選。其他差異不採用，原候選及斜線 0 證據保留，每列仍待人工確認。兩次複核不是兩個獨立正確率保證。
- 複核模型固定 revision `b8f84f0b80c529de40b4fbb3544b84fa7233a513`，21,159,378 bytes，SHA-256 `5435fd747c9e0efe15a96d0b378d5bd157e9492ed8fd80edf08f30d02fa24634`。複核字典保留官方 ASCII 索引，非 ASCII 輸出標成無效字元而不刪除，避免錯誤拼成合法編號。兩個模型合計約 29 MB；舊模型已快取時僅新增下載約 21 MB。全部在 worker 的 WASM 執行，照片不傳到模型網站。

- DEMO 0.4 已以實際 16 列紙本在桌面 Chromium 回測，修正使用者確認的第 7 列 Y／R、第 11 列 0／6，其餘 14 列的 CTN／鋼號與 DEMO 0.3 相同，包含第 1、2 列斜線 0。這是同一張照片的回測，不代表其他書寫人的正確率或自動註冊資格；原始照片、結果及對照表保存在私人驗證目錄。0.5 自動校正後的結果另列於下方。
